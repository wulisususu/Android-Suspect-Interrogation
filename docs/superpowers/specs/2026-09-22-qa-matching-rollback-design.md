# 案件问答匹配增强与本次匹配回退设计

## 目标

增强案件级正式笔录的自动问答匹配，使口语化固定问题和跨 ASR 片段的问答能够稳定归档；同时提供“回退本次匹配”，只撤销正式笔录中的回答，保留问题、原始对话和证据，并且不影响后续新问答匹配。

## 现状与根因

生产链路由 `QAUnitBuilder` 将 ASR 片段组成 QA 单元，再由 `FormalRecordRouter` 调用本地模型进行分类。当前固定问题主要依赖模型目标 ID 或去标点后的完全相等文本，模型输出不符合 JSON 契约时直接进入待审核；当问题与回答跨单元产生时，回答会被标记为 `ORPHAN_ANSWER`。正式笔录只展示状态不是 `DETACHED` 的 `QuestionRound`，而固定/动态问题本身独立存在。

## 方案

### 1. 规则优先、模型兜底

在模型调用前，针对锁定模板问题做高置信度确定性匹配：统一空白、标点和常见口头语，支持模板项级别的别名/语义变体。至少覆盖“你应何时来公安机关”到“你因何事来公安机关？”这一类问法。规则只在唯一候选且问题确实包含问句特征时生效，避免把普通陈述强行写入正式笔录。

模型正常返回时保留现有策略；模型返回无效 JSON、非法目标或策略校验失败时，再使用同一规则做回退。规则回退使用原始回答，不让模型改写或丢失证据事实。

### 2. 跨片段问答关联

`QAUnitBuilder` 遇到嫌疑人回答但没有当前 OPEN 单元时，先查找同一案件、同一询问会话内最近的、只有问题没有回答且在短时间窗口内的 QA 单元。找到后把回答片段追加到该单元并重新关闭/路由；找不到时才创建 `ORPHAN_ANSWER`。原始片段仍保留，重复消费仍由现有片段归属约束阻止。

### 3. 回退

新增案件级回退接口，以 QA 单元为入口定位其创建的正式问答轮次。回退时：

- 将对应 `QuestionRound` 标记为 `DETACHED`，使其不再出现在正式笔录轮次列表；
- 重新计算目标问题的规范回答，使用最近一条未回退轮次，没有则清空；
- QA 单元改为 `ROLLED_BACK`，保留分类、原始问题、原始回答、片段 ID 和模型证据；
- 写入审计事件；
- 不删除 `CaseQuestion`、QA 单元、ASR 片段，不设置问题禁用标记。

因此左侧正式笔录会继续显示问题，只显示空回答；后续新的 QA 单元仍可对同一问题创建新轮次。

### 4. UI

在实时对话的“笔录归档处理”状态列表中，`APPLIED` 项显示“回退本次匹配”。点击后调用案件级回退接口，刷新工作区；`ROLLED_BACK` 项显示“已回退”，不再提供重复回退按钮。

## 验证标准

1. “你应何时来公安机关”与“我偷了一个笔记本”能够匹配到 `opening-reason`，并进入正式笔录。
2. “这是行政案件权利义务告知书……”与下一条“好的我认字”能够组成同一 QA 单元，不再产生 `ORPHAN_ANSWER`。
3. 回退一条已应用轮次后，目标问题仍存在、回答为空、原始对话和 QA 单元仍存在。
4. 回退后新的同问题问答仍能生成新的正式轮次。
5. 既有后端路由、QA 构建、模板工作区和前端类型测试全部通过。
