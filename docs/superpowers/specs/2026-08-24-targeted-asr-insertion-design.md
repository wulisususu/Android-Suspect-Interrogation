# 定点语音转写插入设计

## 目标

在正式询问笔录页面中，用户先点击已有“问”或“答”文本框并放置光标，再启动录音。录音过程中只展示实时转写预览；用户停止录音后，最终识别文本一次性插入原光标位置，并自动保存为该条正式问答的修订。

该功能同时修复当前停止录音时过早清除活动会话、导致最终 ASR 结果无法保存的问题。

## 范围

本次支持已有正式问答文本框，不扩展到底部“新增记录”输入框。笔录已冻结、审讯不可记录或未选择目标问答时不得启动定点录音。

保留现有待确认片段机制，作为没有定点目标、外部流程停止录音或自动写入失败时的数据保护路径。成功写入目标问答的片段不再出现在待确认列表中。

## 用户交互

1. 用户点击某条“问”或“答”的文本框，并把光标放在需要插入的位置。
2. 页面记录目标案件、正式记录 ID、光标起止位置和当前文本，并对目标文本框显示“录音将写入此处”的视觉状态。
3. 用户点击“录音”。如果没有有效目标，页面提示“请先点击要写入的问或答”，且不启动麦克风。
4. 录音期间，ASR 的中间结果只显示在独立的实时转写区域，不修改正式文本。
5. 用户点击“停止”。按钮保持忙碌状态，直到 native 层完成最终解码并保存本次录音产生的临时片段。
6. 如果最终文本有效：
   - 光标没有选中文本时，在光标处插入；
   - 光标选中文本时，以识别结果替换选中内容；
   - 自动保存该条问答修订；
   - 将本次片段原子地标记为已应用到该记录；
   - 重新聚焦目标文本框，并把光标放在插入文字末尾。
7. 如果最终文本为空，原文保持不变，并提示“本次录音未识别到有效文字”。

## 前端状态与数据流

`InterrogationPage.vue` 负责捕获 textarea 的选择区间并维护当前录音目标。目标结构只包含当前页面可以验证的数据：

```ts
interface AsrInsertionTarget {
  caseId: string
  recordId: string
  selectionStart: number
  selectionEnd: number
  sourceText: string
}
```

点击录音时再次验证目标案件、记录是否仍属于当前页面，以及文本框是否可编辑。页面切换案件、笔录冻结或目标记录消失时立即清除目标。

停止录音事件把目标传给 interrogation store。Store 保存停止前的 `captureSessionId`，调用 `asr.capture.stop`，只选取返回片段中属于本次 capture session 的片段，按 `ordinal` 排序后拼接识别文本。文本插入逻辑放在可独立测试的纯 TypeScript 函数中。

Store 随后调用新的 native RPC，把目标记录、新的完整文本和本次片段 ID 一次提交。成功后用后端返回的正式记录更新当前案件 transcript；失败时不从待确认列表移除片段。

## Android 最终结果落盘

当前 `AsrCaptureSessionManager.stop()` 在调用 `asr.stop()` 前把 `active` 设为 `null`。Sherpa 在停止过程中才回调最终结果，因此 `onFinalResult()` 会直接返回。

新的停止顺序为：

1. 在锁内标记活动会话正在停止，但保留活动对象。
2. 关闭音频写入并调用 `asr.stop()`，等待音频线程和最终解码结束。
3. `onFinalResult()` 将最终结果加入该活动会话的待落盘队列。
4. 回到 capture 单线程 dispatcher 后，按顺序把队列写入临时片段表。
5. 更新 capture session 为 `STOPPED`，最后清除 `active`。
6. 返回包含最终片段的最新状态。

停止操作必须幂等；重复停止返回最新状态，不重复创建片段。最终结果为空时不创建临时片段。

## 原子写入正式问答

新增 `asr.fragment.applyToRecord` RPC，输入为：

```json
{
  "caseId": "CASE-...",
  "recordId": "record-id",
  "fragmentIds": ["fragment-id"],
  "text": "插入后的完整正式文本"
}
```

Android 后端在一个 Room 事务中完成：

1. 验证案件存在且审讯状态允许编辑。
2. 验证目标正式记录属于 `caseId`。
3. 验证所有片段属于同一 `caseId`、处于 `PENDING`，且来自本次 capture session。
4. 使用“语音转写插入”作为修订原因更新目标正式记录，保留旧版本。
5. 将片段标记为 `CONFIRMED`，`confirmedQaId` 指向目标记录。
6. 写入包含记录 ID、片段 ID 和 capture session ID 的审计事件。
7. 返回更新后的正式记录和已处理片段。

任何一步失败都回滚整个事务，片段继续保留为待确认，正式问答不发生部分更新。

## 文本插入规则

选择位置按 JavaScript 字符串索引处理，并在插入前限制到 `0..sourceText.length`。如果选择起止顺序颠倒则先归一化。

识别结果只去除首尾空白，不擅自添加标点或改写内容。最终文本以：

```text
sourceText[0..selectionStart] + recognizedText + sourceText[selectionEnd..]
```

组成。这样在句中插入、段尾追加和替换选中文字都使用同一规则。

## 错误处理

- 未选择目标：不启动录音，显示明确提示。
- 目标案件或记录变化：停止自动写入，片段进入待确认列表。
- 无有效识别文本：不更新记录，显示明确提示。
- 最终片段保存失败：capture 状态显示真实错误，保留录音文件。
- 原子写入失败：正式记录不变，片段保持待确认，可人工编辑确认。
- 案件切换：目标、录音事件和异步结果都按 `caseId + generation` 隔离，旧案件结果不得写入新案件。
- 笔录冻结：前端禁止启动，Android 后端再次拒绝写入。

## 测试与验收

### 前端自动测试

- 光标位于句中时正确插入文本。
- 光标位于段尾时正确追加文本。
- 选中一段文字时正确替换。
- 越界或反向选择区间被安全归一化。
- 没有目标时不触发 capture start。
- 只应用当前 capture session 的片段。
- 空识别结果不修改原文。
- 案件切换后忽略旧录音结果。

### Android 自动测试

- `stop()` 在最终回调落盘后才返回。
- 非空最终结果只创建一个片段，重复停止不重复创建。
- 空最终结果不创建片段。
- 应用片段到正式记录时同时生成修订并更新片段状态。
- 案件不匹配、记录不匹配或片段状态错误时事务回滚。

### RK3576 真机验收

1. 点击已有问题中间，录音并停止，文字插入原光标处并自动保存。
2. 点击已有回答末尾，录音并停止，文字追加到末尾并自动保存。
3. 选中文字后录音，最终文本替换选中部分。
4. 不选择问答直接点击录音，页面提示选择目标且麦克风不启动。
5. 说话内容无法识别时原文不变并显示原因。
6. 自动保存失败时，识别文本仍可在待确认片段中找到。
7. 切换案件后不得把上一案件的录音写入当前案件。
