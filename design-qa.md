# Linux Kiosk UI Restoration QA

## Scope

This report covers the high-fidelity restoration of the former Android WebView interrogation experience on the Linux `linux-adaptation` branch. The goal is not to recreate Android platform code. The goal is to preserve the established operator workflow and kiosk interaction model while using the Linux FastAPI + Vue runtime.

Validated code SHA: `94b99004b1b700b1dbbc65f33ea9c8e47cdf5cc4`.

## Source of Truth

The old APK was a full-screen WebView. The useful operator UI baseline is therefore the maintainable Vue source, not Android XML widgets.

Primary structural baseline:

- Commit `1cacc446af3be0bcadd68513d3e5aa42b7e20f0c` — `add maintainable Vue interrogation source`.
- Old interrogation workspace structure: top case/device status + explicit session controls + three working columns for timeline, live Q/A transcript and fact matrix.

Important clarification:

- `frontend/assets/public/assets/screen_preview-inquiry.jpg` is a **suspect-side screen preview** asset. The image itself contains the title `嫌疑人端屏幕预览`; it is not the operator's main interrogation-workbench screenshot and is therefore not used as a pixel-for-pixel baseline for the operator UI.
- The later A4-style editable-document redesign was introduced after the original Vue workbench and is treated as product drift for the main interrogation interaction surface. Document freeze/signature capabilities are retained without keeping the A4 editor as the primary workspace.

## Visual Review

### Interrogation workbench

Passed for the intended fixed desktop/touch-terminal layout.

- Restored the workbench model instead of the A4 document-editor model.
- Fixed three-area working surface remains visible at both 1920×1080 and 1920×900.
- Left area: subject/case identity and case counters.
- Center area: editable Q/A records, role differentiation, record numbering and bottom recording/manual-entry composer.
- Right area: current-stage guidance, ASR/runtime state, AI case-analysis action and document/signature operations.
- Top area: case identity, runtime/device state, workspace tabs and explicit session controls.
- Start/pause/resume/end are operator actions; opening the interrogation tab no longer silently starts or resumes a session.
- No mobile card-stack transformation is used for the primary kiosk pages. Global layout uses a desktop minimum width and the restored main pages are fixed workstation/touch layouts.
- 1920×900 capture keeps the principal controls and composer within the terminal workflow without collapsing into a mobile layout.

### Case list

Passed for kiosk usage.

- Full-width desktop case rows instead of mobile cards.
- Large row hit areas and a prominent `新建询问` action.
- Identity source, stage and case state are visible as operational status tags.
- No hover-only action is required to open a case.

### Identity intake

Passed for the Linux front-end flow with mock/runtime capability states.

- Large modal/workstation surface with three explicit modes: physical identity-card reader, OCR and manual input.
- Reviewed identity fields remain editable before confirmation.
- The Linux runtime can read a card as a preview before a case exists; that preview no longer creates an orphan Person row.
- On confirmation the reviewed identity is bound to the newly created case through `/api/v1/identity/confirm`, advancing the workflow to `IDENTITY_READY` without a hidden second hardware read.
- Bound identity fields are subsequently exposed by case reads, so the case list/workbench retains the confirmed identity after refresh.

## Functional Contract Fixes Included in the Restoration

The visual restoration uncovered two P0 integration defects that were fixed instead of being hidden by UI mocks:

1. Session Runtime routes now use the canonical FastAPI endpoints under `/api/v1/cases/{case_id}/session/*` for start, pause, resume, stage and finish.
2. Identity intake now has an explicit reviewed-identity confirmation path, preserving the backend rule that a case must reach `IDENTITY_READY` before interrogation can start.

The Browser screenshot QA also now waits on the actual `/health/ready` endpoint and seeds its case through the same canonical identity/session workflow.

## Known QA Boundary

The GitHub-hosted screenshot runner does not include the same Chinese font inventory as the target kiosk. Chinese glyphs can therefore appear as missing-glyph boxes in the CI PNGs. Layout geometry, control placement, scrolling and fixed-terminal behavior were reviewed from those captures; final Chinese font rendering should be checked on the target Linux kiosk where the production CJK fonts are installed.

Real hardware verification is intentionally not marked complete by this report. It must only be marked complete after vendor/card-reader, microphone/ASR and signature-device checks run against the actual devices.
